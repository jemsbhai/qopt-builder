The command line

The builder as a program you run from a terminal. It does what the page does, on problems read from files, with no limit on their size, and it can hand the result to a script.

If the words are new, the primer explains them, and the user guide explains each result on the page. This page assumes you can open a terminal and run Python.

Setting up

The command line is part of the Python package in the repository. Get the repository, install what it needs, and run the commands from the repository's own folder:

git clone https://github.com/jemsbhai/qopt-builder
cd qopt-builder
pip install -r requirements.txt

Check that it runs:

python -m qopt_builder --version
qopt-builder 0.1.0

Every command starts with python -m qopt_builder, followed by one of three words: run, package or presets. Add --help after any of them to see its options.

A first run

The package carries the same preset problems as the page. Run the first of them, the demo graph:

python -m qopt_builder run --preset demo
Problem: Demo graph: weighted MaxCut, 6 nodes (preset demo)
Coupling density: 0.53 (8 of 15 pairs)
Recommendation: exact+qaoa, p = 3
 - n=6 <= 24: an exact classical solve is cheap and certifies the quantum result; recommending exact with QAOA built alongside for comparison.
 - coupling density 0.53 is high: deeper QAOA (p=3) earns its depth on dense graphs.
Certified optimum: -8.000 at x = [0 1 0 0 1 0]
As a cut: weight 8.000
QAOA circuit: 6 qubits, depth 19, 48 gates (6 H, 24 RZZ, 18 RX), 6 free parameters
Angle scan: best expected cost -7.308 over 200 samples (seed 20261110)
Gap to the certified optimum: 0.692

That is the whole pipeline: the recommendation with its reasons, the certified optimum, the circuit, and a first look at how close the circuit gets. Reading the report goes through it line by line.

Your own problem

A problem is a plain text file in one of two forms. They are the forms the page's text boxes take, so anything you typed there can be saved to a file and used here, and the user guide's sections on edge lists and matrices apply word for word.

A graph, for MaxCut

One edge per line: two node numbers and, if you want one, a weight. This file is the demo graph:

graph.txt
# two triangles joined by two edges
0 1
0 2
1 2
1 3 2
2 4
3 4
3 5
4 5 2
python -m qopt_builder run --edges graph.txt
Problem: MaxCut on 6 nodes, 8 edges (graph.txt)
Coupling density: 0.53 (8 of 15 pairs)
Recommendation: exact+qaoa, p = 3
 - n=6 <= 24: an exact classical solve is cheap and certifies the quantum result; recommending exact with QAOA built alongside for comparison.
 - coupling density 0.53 is high: deeper QAOA (p=3) earns its depth on dense graphs.
Certified optimum: -8.000 at x = [0 1 0 0 1 0]
As a cut: weight 8.000
QAOA circuit: 6 qubits, depth 19, 48 gates (6 H, 24 RZZ, 18 RX), 6 free parameters
Angle scan: best expected cost -7.308 over 200 samples (seed 20261110)
Gap to the certified optimum: 0.692

The report is the one above, because it is the same problem. Only the first line differs: it names the file.

The graph has one more node than the largest number in the file. If your graph ends with nodes that have no edges at all, say how many nodes there are with --nodes.

Any other problem, as a QUBO matrix

One row of the matrix per line. The cost of an assignment x is xTQx plus an offset, and the builder looks for the lowest cost. The offset is given on the command line:

matrix.txt
-1  2  0
 0 -1  2
 0  0 -1
python -m qopt_builder run --qubo matrix.txt --offset 1
Problem: QUBO on 3 variables, offset 1 (matrix.txt)
Coupling density: 0.67 (2 of 3 pairs)
Recommendation: exact+qaoa, p = 3
 - n=3 <= 24: an exact classical solve is cheap and certifies the quantum result; recommending exact with QAOA built alongside for comparison.
 - coupling density 0.67 is high: deeper QAOA (p=3) earns its depth on dense graphs.
Certified optimum: -1.000 at x = [1 0 1]
QAOA circuit: 3 qubits, depth 13, 21 gates (3 H, 3 RZ, 6 RZZ, 9 RX), 6 free parameters
Angle scan: best expected cost -0.212 over 200 samples (seed 20261110)
Gap to the certified optimum: 0.788

From another program

Give - as the file name and the problem is read from standard input, so another program can write it straight in:

python make_graph.py | python -m qopt_builder run --edges -

Here make_graph.py stands for any program of yours that prints an edge list.

Reading the report

LineWhat it says
ProblemWhat was read and where from: the number of nodes and edges of a graph, or the number of variables of a matrix.
Coupling densityThe share of pairs of variables that appear together in the cost. For a graph, the share of pairs of nodes joined by an edge. See the problem card.
RecommendationWhat the builder decided, and the number of layers p. The indented lines under it are its reasons. See the recommendation card.
Certified optimumThe lowest cost there is, found by checking every assignment, and the assignment that reaches it, variable 0 first. Computed up to 24 variables. For a graph, the next line gives the same answer as the weight of the cut.
QAOA circuitThe size of the circuit that was built: qubits, depth, gates by kind, and the angles still to be chosen. See the circuit card.
Angle scanThe circuit is simulated at 200 random settings of its angles, and this is the best expected cost among them. Simulated up to 14 variables.
GapHow far that best expected cost is above the certified optimum. Zero would mean the circuit gives a best answer every time.

The page goes one step further than the scan: it refines the best setting it found. The command line reports the scan as it is, which is why the page and the command line show different expected costs for the same problem. The user guide has the details.

Options of run

OptionWhat it does
--edges FILEThe problem: a graph, as an edge list.
--qubo FILEThe problem: a QUBO matrix.
--preset NAMEThe problem: one of the presets. Exactly one of these three is needed.
--nodes NWith --edges: the number of nodes, when the last ones have no edges.
--offset XWith --qubo: a constant added to every cost.
--budget QUBITSThe number of qubits your machine has. A problem with more variables than that is refused.
--layers PBuild this many layers instead of the recommended number. The report says that you did.
--samples NHow many settings the scan tries.
--seed SThe seed of the scan's random settings. The same seed gives the same report.
--no-scanBuild the circuit and do not simulate it.
--jsonPrint the report as JSON.
--drawAlso print a drawing of the circuit, made by Qiskit.

A qubit budget that is too small stops the run before anything is built:

python -m qopt_builder run --preset demo --budget 4
Problem: Demo graph: weighted MaxCut, 6 nodes (preset demo)
Coupling density: 0.53 (8 of 15 pairs)
Recommendation: none
 - n=6 <= 24: an exact classical solve is cheap and certifies the quantum result; recommending exact with QAOA built alongside for comparison.
 - n=6 exceeds the qubit budget of 4: no full-width circuit fits; the builder will refuse rather than silently truncate.
Refused: no circuit built.

With the scan left on, scan holds its best expected cost, the angles that gave it (gammas and betas), the number of samples, the seed, and the gap. After a refusal, refused is true and the parts that were not computed are null. notes says in words what was left out and why.

Packaging for hardware

package takes the same options as run, prints the same report, and then writes a hardware package: a folder with the problem, the circuit with its angles filled in, and a script that runs the circuit on a simulator or on an IBM quantum computer.

python -m qopt_builder package --preset demo --out demo-package
Problem: Demo graph: weighted MaxCut, 6 nodes (preset demo)
Coupling density: 0.53 (8 of 15 pairs)
Recommendation: exact+qaoa, p = 3
 - n=6 <= 24: an exact classical solve is cheap and certifies the quantum result; recommending exact with QAOA built alongside for comparison.
 - coupling density 0.53 is high: deeper QAOA (p=3) earns its depth on dense graphs.
Certified optimum: -8.000 at x = [0 1 0 0 1 0]
As a cut: weight 8.000
QAOA circuit: 6 qubits, depth 19, 48 gates (6 H, 24 RZZ, 18 RX), 6 free parameters
Angle scan: best expected cost -7.308 over 200 samples (seed 20261110)
Gap to the certified optimum: 0.692
Hardware package written: demo-package (README.txt, problem.json, circuit.qasm, run_on_ibm.py, requirements.txt)
Start with README.txt in that folder: step 1 runs the circuit on a simulator.

Running on hardware explains what is in the folder and how to use it. The options that package adds:

OptionWhat it does
--out PATHWhere to write. A name ending in .zip gives one zip archive; any other name gives a folder. Without it the folder is qopt-package.
--gammas ANGLES
--betas ANGLES		The angles to put in the circuit, one of each per layer, separated by commas. Without them the package gets the best angles of the scan. A problem too large to simulate has no scan, so it needs these.
--forceWrite even if the folder or archive is already there.

package has no --no-scan, --json or --draw.

The presets

python -m qopt_builder presets
demo             Demo graph: weighted MaxCut, 6 nodes
                 Two triangles joined by two edges, with weights 1 and 2. A triangle always
                 leaves one of its edges uncut, so the best cut misses one weight-1 edge in
                 each.
tree-14          Sparse tree: MaxCut, 14 nodes
                 A binary tree with unit weights. A tree can be two-coloured level by level, so
                 every edge can be cut. This is the largest size the browser simulates.
ring-10          Ring: MaxCut, 10 nodes
                 A ring of ten nodes with unit weights. An even ring alternates sides and cuts
                 every edge.
weighted-8       Dense weighted graph: MaxCut, 8 nodes
                 Sixteen weighted edges on eight nodes, more than half of all possible pairs.
chorded-ring-24  Chorded ring: MaxCut, 24 nodes
                 A problem at the exact-solve limit of 24 variables. Every node is joined to its
                 neighbours one and two steps around a ring: 48 unit edges, full of triangles.
                 Each triangle leaves an edge uncut, which bounds the cut at 36, and the pattern
                 1100 repeated reaches it. Too large to simulate, so the builder certifies the
                 optimum and builds the circuit only.
vertex-cover-6   Vertex cover: QUBO, 6 variables
                 Minimum vertex cover, a different problem on the demo graph: pick the fewest
                 nodes that touch every edge. Each chosen node costs 1 and each uncovered edge
                 costs 2, which puts linear terms on the diagonal and a constant offset of 16.
                 The optimum cost is the size of the smallest cover.
dense-qubo-6     Dense symmetric QUBO, 6 variables
                 A matrix entered in symmetric form, with every pair of variables coupled and
                 linear terms on the diagonal.

They are the problems in the page's list, described in the user guide.

Errors and exit status

A problem that cannot be used is reported in one line, with the file and the line where it went wrong, and nothing else is printed:

broken.txt
0 1
1 1
python -m qopt_builder run --edges broken.txt
error: broken.txt: Line 2: an edge cannot join node 1 to itself.

The messages are the ones the page shows. The user guide lists them with what to do about each.

The exit status tells a script what happened:

StatusMeaning
0A circuit was built. For package, the package was written too.
1The builder refused the problem: it has more variables than the qubit budget.
2The input could not be used: a file that is missing or malformed, an option that is wrong, or a package that would replace one already there.

In PowerShell the status of the last command is in $LASTEXITCODE. In bash it is in $?.

From Python

The command line is a thin layer over functions you can call yourself. The same run as a short program:

from qopt_builder import build_qaoa, maxcut_qubo, recommend, scan_angles

problem = maxcut_qubo([(0, 1), (1, 2), (0, 2)], 3)    # a triangle

choice = recommend(problem)
print(choice.algorithm, "with p =", choice.params["p"])

cost, x = problem.brute_force()
print("certified optimum", cost, "at", [int(v) for v in x])

circuit, angles = build_qaoa(problem, choice.params["p"])
print(circuit.num_qubits, "qubits, depth", circuit.depth())

scan = scan_angles(problem, choice.params["p"])
print("best expected cost", round(scan.value, 3))

It prints:

exact+qaoa with p = 3
certified optimum -2.0 at [1, 0, 0]
3 qubits, depth 13
best expected cost -1.989

circuit is an ordinary Qiskit QuantumCircuit, so everything Qiskit can do with a circuit is open to you from there. print(circuit.draw()) shows it as a drawing.

The functions, all imported from qopt_builder:

FunctionWhat it gives
maxcut_qubo(edges, n)A problem from a list of edges on n nodes.
QUBO(matrix, offset)A problem from a matrix.
parse_edge_list(text)
parse_matrix(text)		The contents of a problem file, turned into the edges or the matrix.
recommend(problem, qubit_budget)The recommendation: the algorithm, the number of layers, and the reasons.
problem.brute_force()The certified optimum: its cost and its assignment.
build_qaoa(problem, p)The circuit with p layers, and the angles it leaves open.

Quantum Optimisation Circuit Builder

Describe an optimisation problem and the builder does three things, in the open: it recommends an algorithm and states its reasons, it builds the QAOA circuit for that recommendation, and it solves the problem exactly so the quantum result has something to be checked against. Everything on this page runs in your browser. The same pipeline ships as a Python package built on Qiskit.

      How it works

      Intake

      Problems enter as a QUBO: a matrix Q and an offset, minimised over binary variables. MaxCut on a weighted graph converts to this form exactly, with no approximation in the conversion.

      Recommendation

      A small set of stated rules reads the problem features: size n, coupling density, whether an exact classical answer is cheap, and an optional qubit budget. Every recommendation carries its rationale in plain text, so any choice can be overridden with the reason in view.

      Circuit factory

      The QUBO is converted to its Ising form and the QAOA circuit is built at the recommended depth p: a phase separator with ZZ rotations for couplings and Z rotations for linear terms, and an X mixer, per layer.

      Validation

      For n up to 24 the exact optimum is computed by enumeration, so the QAOA expectation and its most likely outcomes are reported next to a certified answer, not next to another heuristic.

      Validation record

      The Python implementation (repository, run_demo.py) was verified end to end on the demo graph used as the first preset on this page:

      • Recommendation: exact + QAOA, p = 3, with both rationales printed.
      • Brute-force optimum: cost -8.000 (a cut of weight 8 on the 6-node graph).
      • QAOA circuit: 6 qubits, depth 19, 6 free parameters.
      • Best expectation from a 200-point coarse angle scan: -7.31, against the certified optimum of -8.00.

      This page recomputes the same pipeline live. The exact optimum it reports for the demo preset must read -8.000; if it does not, the page is wrong, not the record. The scan value on this page differs from the Python one because the browser draws its scan angles from its own seeded random stream; it is the same on every visit. The page then refines the best scanned angles, which the demo script does not do.

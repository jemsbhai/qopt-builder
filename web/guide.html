Using the builder

How to run the builder page, how to read each card it shows, and how to give it a problem of your own. If the vocabulary is new, the primer comes first.

A first run

Open the builder. It runs the demo graph as soon as the page loads, so there are results on screen before you touch anything. Nothing is sent anywhere: the whole computation happens in your browser.

To run something else, work down the left-hand column:

  1. Problem. Pick a preset from the list, or pick one of the two custom entries and type your own problem.
  2. Hardware budget. Optional. Enter the number of qubits your machine has, or leave it empty.
  3. Press Run the builder. The line under the button says what the page is doing, and reports any problem with the input in red.

The results appear on the right as a stack of cards, in the order the builder works: the problem, the recommendation, the exact solve, the circuit, and the simulated run.

Reading the results

The examples below are what the page shows for the demo graph, the first preset.

Problem

For a graph, a drawing of it with the weight on each edge, and a line such as:

MaxCut on 6 nodes, 8 edges. Coupling density 0.533.

The coupling density is the share of node pairs joined by an edge. Once the exact solve has run, the drawing is coloured: the two colours are the two groups of the best split, and the highlighted edges are the ones it cuts. For a QUBO matrix there is no drawing, and the line gives the number of variables, the offset if there is one, and the density.

Recommendation

What the builder decided to do, then its reasons as a list. For the demo graph the heading reads exact+qaoa (p = 3).

  • exact+qaoa means the problem is small enough to solve exactly, so the builder does that and builds a QAOA circuit alongside for comparison. This is what you get up to 24 variables.
  • qaoa on its own means the problem is too large to check completely. The circuit is built, and its result will not be certified.
  • p is the number of layers in the circuit. It follows from the coupling density: 1 layer up to 0.15, 2 up to 0.5, 3 above that.

Each reason is a full sentence with the number that triggered it, so you can see exactly why the choice was made.

Builder refusal

This card replaces the recommendation when the problem has more variables than the qubit budget you entered. It gives the reason, and nothing below it is built. See the qubit budget.

Exact classical solve

Certified optimum cost -8.000 at x = [0, 1, 0, 0, 1, 0]
For MaxCut this is a maximum cut of weight 8.000.

The builder computed the cost of every assignment and this is the lowest. The list x is the assignment that achieves it, variable 0 first: here nodes 1 and 4 are in one group and the rest in the other. Costs are minimised, so for MaxCut the cost is minus the weight of the cut.

When several assignments are equally good, the page reports the one with the lowest number. The demo graph has 6 best splits and this is the first. The card also says how long the check took in your browser.

QAOA circuit

6 qubits, depth 19, 48 gates (6 H, 24 RZZ, 18 RX), 6 free parameters

Then the circuit itself. Each line is a qubit, time runs left to right, a box is a gate on one qubit, and two linked dots are one gate on two qubits. Colour marks the layer. Long circuits scroll sideways.

  • Qubits: one per variable.
  • Depth: the number of time steps when gates on different qubits run side by side. It is the number to watch for real hardware.
  • Gates: an H on every qubit, then in each layer one RZZ per edge and one RX per qubit. For the demo graph that is 6 + 3 × (8 + 6).
  • Free parameters: the angles still to be chosen, a gamma and a beta for each layer.

QAOA run

Coarse scan best expectation -6.664. After refinement: -7.187.
Certified optimum -8.000; gap after refinement 0.813.

The page simulates the circuit to find good angles, in two stages. The scan tries 200 random settings and keeps the best. The refinement then improves that setting step by step. Both numbers are expected costs: the average cost you would get from many measurements. The gap is how far the refined circuit still is from the certified optimum.

The chart shows the 200 scanned values as a line, the certified optimum as a dashed line below them, and the refined value as a dot. No value can be below the dashed line.

The table lists the bit strings you would measure most often at the refined angles, with the probability and the cost of each. Rows marked optimal are best answers. In a good run they are near the top.

This card needs a full simulation, so it is filled in only up to 14 variables. For a larger problem it says that no run was simulated.

Entering your own problem

A graph, as an edge list

Choose Custom MaxCut edge list and type one edge per line: two node numbers, then the weight.

0, 1, 1
1, 2, 2.5
2, 0
  • Nodes are numbered from 0. The graph has one more node than the largest number you use, so skipping a number leaves a node with no edges.
  • Numbers may be separated by spaces or commas. Blank lines are ignored.
  • The weight is optional and is 1 when left out. It may be negative or fractional.
  • The direction of an edge does not matter: 2, 0 and 0, 2 are the same edge. An edge written twice counts twice.
  • An edge cannot join a node to itself.

Any other problem, as a QUBO matrix

Choose Custom QUBO matrix and type the matrix one row per line. The cost of an assignment x is xTQx plus the offset, and the builder minimises it.

-1  2  0
 0 -1  2
 0  0 -1
  • The matrix must be square: as many numbers in every row as there are rows.
  • The diagonal holds the cost of each variable on its own. An entry off the diagonal is a coupling between two variables.
  • Write each coupling either once, on one side of the diagonal (a triangular matrix, as above), or split in half over both sides (a symmetric matrix). A matrix that is neither is rejected, because it is most often a typing mistake.
  • The constant offset is optional. It shifts every cost by the same amount and does not change which assignment is best.

The qubit budget

The budget is the number of qubits on the machine you have in mind. A problem needs one qubit per variable. If you enter a budget and the problem needs more, the builder refuses: it shows a refusal card with the reason and builds no circuit.

It refuses instead of cutting the problem down, because a circuit for part of your problem answers a different question, and nothing in its output would tell you so. To see a refusal, run the demo graph with a budget of 4.

The budget is a whole number, 0 or more. Leave the box empty for no limit.

Limits

The guided demo

The guided demo plays the same pipeline as an animation on one screen, with the circuit assembled gate by gate and each edge of the graph flying to the gate that encodes it. It is the quickest way to see what the builder does, and it is made to be recorded.

KeyWhat it does
SpaceStart, pause and resume.
Right arrowSkip to the end of the current stage.
RRestart from the beginning.
HShow or hide the controls.
CShow or hide the captions.

Options go in the address after a question mark, joined by &, for example demo.html?preset=ring-10&speed=2.

OptionWhat it does
preset=NAMEThe problem to play: demo, tree-14, ring-10, weighted-8, chorded-ring-24, vertex-cover-6 or dense-qubo-6.
budget=NA qubit budget. budget=4 with the demo graph shows a refusal.
speed=N0.5, 1 or 2.
autoplay=1Start as soon as the page opens, without waiting on the title card.
controls=0Hide the controls, for a clean recording. Press Space to start.
captions=0Hide the captions.

Questions people ask

Is any of this running on a quantum computer?

No. The circuits are run by a simulator inside your browser, which is exact and has no noise. The Python package builds the same circuits as Qiskit objects, and Qiskit can run those on a simulator or on hardware.

Why does the page show -6.664 for the scan when the Python script prints -7.308?

Both try 200 random settings of the angles, and they draw those settings from different random number generators: the page uses a small generator of its own, which gives the same sequence in every browser, and the Python script uses NumPy's. It is the same circuit scored at different angles. Everything that does not depend on the random draw is identical in the two, and the project's tests check that: they hand the page's 200 settings to Qiskit and require the same 200 values back, to nine decimal places.

The recommendation says p = 3. Can I build another depth?

Not on the page, which builds what it recommends. In the Python package you can: build_qaoa(problem, p) takes any number of layers.

Why is the QAOA run card empty for my problem?

The run needs a full simulation, which the page does up to 14 variables. Larger problems still get the recommendation, the circuit, and the certified optimum if they have 24 variables or fewer.

Will I get the same numbers tomorrow?

Yes. Nothing on the page depends on the time or on chance: the random settings of the scan come from a fixed seed, so a problem gives the same numbers every time you run it.

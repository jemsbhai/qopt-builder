The quantum computing behind this tool

A primer for programmers who have not met quantum computing before. It assumes no physics. By the end you can read every card the builder shows and say what each number on it means.

Words with a dotted underline are explained in the glossary. Boxes marked "The maths" can be skipped; nothing later depends on them.

The problem: many yes-or-no choices

The builder works on one kind of problem. There are n decisions, each a yes or a no. Every combination of answers has a cost, and the task is to find the combination with the lowest cost. Each decision is a variable that is 0 or 1, and one full set of answers is an assignment, written as a string of bits such as 010010.

The running example is MaxCut. Take a graph whose edges have weights, and split its nodes into two groups. An edge is cut when its two ends land in different groups. The goal is the split that cuts the most weight. One bit per node says which group the node is in, so a graph with n nodes is a problem with n variables.

What makes such problems hard is counting. With n yes-or-no choices there are 2n assignments, and that number doubles with every variable added.

VariablesAssignmentsWhat that means

Clever classical algorithms avoid checking everything and do well on many instances. Still, for problems of this family nobody knows a method that is fast on all of them, which is why they are a standard testing ground for new kinds of computer.

In this tool. Every problem is stored in one standard form called a QUBO: a table of numbers Q, one row and one column per variable. A number on the diagonal is the cost of setting that variable to 1 on its own. A number off the diagonal is a coupling: an extra cost paid when both of its variables are 1. MaxCut converts to this form exactly, and any other problem can be entered as a QUBO directly.

The maths: the cost of an assignment

cost(x) = xT Q x + offset,   each xi in {0, 1}

Because xi is 0 or 1, xi2 = xi, so the diagonal entry Qii is a linear term. For two different variables the cost picks up Qij + Qji when both are 1. That sum is the coupling, which is why the builder accepts a matrix that is symmetric (the coupling split over both entries) or triangular (the coupling written once).

For MaxCut, an edge of weight w between nodes i and j is cut when xi and xj differ, which is the expression xi + xj - 2 xi xj. The builder minimises, so the cost is minus the weight cut. The best cut of the demo graph, weight 8, therefore shows up as a cost of -8.000.

A qubit, in the detail you need

A bit is 0 or 1. A qubit, when you read it, also gives 0 or 1. The difference is in what it holds before you read it.

Before it is read, a qubit is described by two numbers called amplitudes, one for the answer 0 and one for the answer 1. Reading the qubit is called measurement. A measurement returns 0 or 1 at random, and the size of each amplitude sets how likely its answer is. A qubit with weight on both answers is said to be in a superposition.

Several qubits together have one amplitude for every bit string they could return: 2 qubits have 4, 3 qubits have 8, and n qubits have 2n. A quantum computer changes all of those amplitudes with a short list of operations. It cannot show them to you. A measurement returns one bit string, chosen at random according to the amplitudes, and running the same computation again may return a different one. Each run is called a shot.

This is the point most often told wrongly. A quantum computer does not "try every answer at once and pick the best". It returns one answer per run. The skill lies in arranging the amplitudes so that good answers are the likely ones.

In this tool. Each variable of the problem becomes one qubit, and a measured bit string is an assignment: a candidate answer. The demo graph has 6 nodes, so its circuit has 6 qubits and 64 amplitudes, one per way of splitting the graph.

The maths: amplitudes and probabilities

The state of n qubits is a list of 2n complex numbers, one per bit string, called the statevector. The probability of measuring a bit string is the squared size of its amplitude, and those probabilities add up to 1.

A complex number has a size and a direction. The direction is called its phase. Phase has no effect on a measurement made straight away, but it decides what happens when amplitudes are later added together: amplitudes pointing the same way reinforce, and amplitudes pointing opposite ways cancel. That is interference, and it is the mechanism every quantum algorithm relies on.

Gates and circuits

A gate is one operation on one or two qubits. It changes amplitudes in a fixed, known way. A circuit is a list of gates applied in order, followed by a measurement. A circuit is to a quantum computer what a program is to an ordinary one.

Circuits are drawn as below. Each horizontal line is a qubit. Time runs from left to right. A box on a line is a gate on that qubit, and two dots joined by a vertical line are one gate acting on two qubits.

The builder uses four kinds of gate. One sentence each is enough to follow the rest of this page.

GateActs onWhat it does
Hone qubitTakes a qubit that is definitely 0 and gives it equal weight on 0 and 1. Used once on every qubit at the start.
RZone qubitTurns the phase of the qubit's 1 answer relative to its 0 answer by a chosen angle. The chances of 0 and 1 stay as they were.
RZZtwo qubitsThe same idea for a pair: the phase turn depends on whether the two qubits agree or differ. This is the gate that writes a coupling into the circuit.
RXone qubitMoves weight between the qubit's 0 and 1 answers by a chosen angle. How the weight lands depends on the phases set earlier.

Two numbers describe the size of a circuit. The gate count is the number of gates. The depth is the number of time steps needed when gates on different qubits run side by side: in the picture, the three H gates share one step. Depth matters on real machines, because qubits lose their state as time passes, so a shallower circuit gives a cleaner result.

QAOA: from a problem to a circuit

QAOA (the quantum approximate optimisation algorithm) is a recipe for building a circuit out of a problem, so that measuring the circuit tends to return low-cost assignments. The recipe has three parts.

  1. Start even. An H gate on every qubit gives every assignment the same chance. For the demo graph that is 1 in 64 each.
  2. Mark by cost. One RZZ gate for every coupling in the problem, all turned by a shared angle called gamma. Together they turn the phase of each assignment's amplitude by an amount that grows with its cost. This block is the phase separator. Nothing is more or less likely yet: the costs are now written into the phases. (Problems other than MaxCut usually need an RZ gate on each qubit here as well. In MaxCut those terms cancel.)
  3. Mix. An RX gate on every qubit, all turned by a shared angle called beta. This lets weight flow between assignments that differ in one bit. Because of the phases from the step before, the flows reinforce for some assignments and cancel for others. This block is the mixer.

Steps 2 and 3 together are one layer. The circuit repeats them p times, each layer with its own gamma and beta, and then measures. The number p is the depth of the algorithm. In the triangle circuit above, p is 1: after the H gates come three RZZ gates, one per edge, and then three RX gates.

The angles are the adjustable part. With badly chosen angles the circuit is no better than guessing. With well chosen ones, low-cost assignments become likely. Finding good angles is done by an ordinary computer: try a setting, estimate how good the circuit's answers are, adjust, and repeat. Algorithms that split the work this way are called variational.

The yardstick for "how good" is the expected cost: the average cost you would get by measuring the circuit many times. Lower is better. It can never go below the true optimum, since no single answer is better than the best one.

More layers can only help in principle. A circuit with one more layer contains the shorter circuit as a special case: set the extra pair of angles to zero and the extra layer does nothing. The paper that introduced QAOA shows that with enough layers the best reachable expected cost approaches the optimum. The price is a longer circuit, which real hardware runs less cleanly, and more angles to tune.

The maths: what the two blocks are

Replace each variable by zi = 1 - 2 xi, which is +1 or -1. The cost becomes a sum of terms hi zi and Jij zi zj, plus a constant. This is the Ising form of the problem, and reading z as the Pauli Z operator turns it into the cost operator C.

phase separator: exp(-i gamma C)   = RZ(2 gamma hi) on each qubit, RZZ(2 gamma Jij) on each coupled pair

mixer: exp(-i beta (X1 + ... + Xn))   = RX(2 beta) on each qubit

The gates within the phase separator commute, so the product of gates is exactly the exponential, with no approximation. The constant term only adds an overall phase, which no measurement can see, so the circuit leaves it out. MaxCut has no h terms, which is why the circuits for graphs on this site contain no RZ gates.

Why the builder also solves it classically

A QAOA result on its own tells you little. An expected cost of -7.187 could be nearly perfect or far off, and nothing in the circuit says which.

So for every problem small enough, the builder also finds the true best answer the plain way: it checks all 2n assignments. That is the exact solve, and its answer is the certified optimum. It is certified in the literal sense that every alternative was looked at. The builder does this up to 24 variables.

Every quantum number is then shown next to that certified answer. For the demo graph the tuned circuit reaches -7.187 against an optimum of -8.000, a gap of 0.813, and one measurement in every two or three returns a best split.

You may ask what the quantum circuit is for, if the classical check already has the answer. On a problem this small, nothing: the check wins. The purpose is to see how QAOA behaves where the truth is known, before relying on it where the truth cannot be checked. Above 24 variables the builder still recommends and builds a circuit, and it says plainly that the result is not certified.

What the recommendation is doing

Before building anything, the builder reads three features of the problem and applies a short list of stated rules. The rules and the reasons are printed with every recommendation, so you can see why a choice was made and disagree with it.

FeatureWhat it isWhat the builder does with it
Size, nThe number of variables, which is also the number of qubits.Up to 24, it solves the problem exactly as well, so the quantum result can be checked.
Coupling densityThe share of variable pairs that have a coupling. The demo graph has 8 edges among 15 possible pairs: 0.53.Up to 0.15 it builds 1 layer, up to 0.5 it builds 2, above that 3. The demo graph gets p = 3.
Qubit budgetHow many qubits your machine has. Optional.If the problem needs more qubits than the budget, the builder refuses and builds nothing. It never drops variables to make a problem fit.

The density rule is a rule of thumb and is presented as one. A sparse graph, close to a tree, gains little from extra layers, while a dense one has more structure for the extra layers to use. It is a sensible starting depth, not a proof that the depth is best.

Simulators and real hardware

Nothing on this site runs on a quantum computer. The circuits are run by a simulator: an ordinary program that keeps all 2n amplitudes in memory and applies each gate to them exactly. A simulator is exact and free of noise, and every circuit result on this site comes from one.

It does not scale, and that is the whole reason quantum hardware is interesting. Each added qubit doubles the memory and the work. The page stops at 14 qubits, 16,384 amplitudes, to stay quick in a browser. At 50 qubits the list of amplitudes alone, at 16 bytes each, would need about 18 petabytes.

A real quantum computer holds those amplitudes physically instead of in memory, which removes that wall and raises others:

  • Every gate is slightly wrong, two-qubit gates most of all, and the errors add up along the circuit.
  • Qubits lose their state with time, so deep circuits suffer more than shallow ones.
  • Most machines can only apply a two-qubit gate between neighbouring qubits. A circuit has to be rewritten to fit the machine, a step called transpilation, and that usually makes it longer.

The result on hardware is therefore worse than the simulated one, by an amount that depends on the machine and on the depth and two-qubit gate count of the circuit. Those two numbers are on every circuit card for that reason.

The builder can take a circuit up to that line. It writes a hardware package: the circuit with its angles filled in, in a form a quantum computer accepts, and a script that runs it and scores what comes back against the certified optimum. The script can also rehearse the run on a simulated copy of a real device, which shows the effects in the list above before any real machine is involved. Running on hardware has the steps.

One more thing should be said plainly. QAOA is a heuristic. There is no proof that it beats the best classical methods on these problems, and this tool does not claim that it does. What the tool offers is a clear path from a problem to a circuit, with the reasoning shown and the answer checked wherever a check is possible.
